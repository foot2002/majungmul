# 블로그 사진·실제 AI 동영상

홍보 글 검토 화면의 **사진에 생동감 더하기**에서 사용한다.

1. 기준 사진과 연출을 선택한다. 음식은 등록된 메뉴만 선택할 수 있다. 제육·구이는 지글거림, 국물은 끓는 모습, 음료는 따르는 모습을 기본 추천한다. 손님 추가에는 매장 내부 사진을 선택한다.
2. **AI 연출 사진 만들기**를 누르면 원본 사진을 OpenAI 이미지 편집 API에 보내 빠진 음식 또는 가상의 성인 손님을 추가한다. 매장 구조·조명과 메뉴 특징을 유지하도록 지시한다.
3. 결과를 확인하고 **블로그 사진 PNG**로 저장하거나 **이 사진을 6초 AI 영상으로**를 누른다. 음식의 기포·김이나 사람의 행동이 움직이는 Kling I2V 영상이다.
4. 완성된 AI 장면은 30초 영상의 가운데 장면에 순서대로 들어간다. 앞뒤는 원본 사진과 방문 안내이며, 선택한 배경음악과 자막을 합성한다. AI 장면은 글당 최대 3개(18초)이다. 아직 영상으로 만들지 않은 AI 사진은 정지 사진으로 포함된다.
5. **AI 장면 포함 30초 영상 완성하기**로 합성하고 파일을 다운로드하여 블로그·SNS에 첨부한다. 완성된 AI 동영상이 0개이면 이 버튼은 비활성화되며, 직접 호출해도 사진 영상으로 대체하지 않는다. **사진 확대·이동 영상만 만들기**를 별도로 펼치고 선택한 경우에만 사진 편집 영상을 만든다. 결과 안내와 파일명에서 `AI장면포함` / `사진편집`을 구분한다. 블로그 자동 발행은 기존 시연 기능이며 이 변경에 포함되지 않는다.

**AI 연출** 표시는 PNG와 30초 영상 픽셀에 포함된다. 원본 사진은 수정하지 않는다. 생성 결과가 실제 메뉴·매장과 맞는지 게시 전에 확인한다. 사진·영상 프롬프트는 화면의 **생성 프롬프트 확인**에서 볼 수 있고, 구현은 `src/lib/ai/scene-prompts.ts`이다. 손님은 실제 방문량을 나타내지 않는 가상의 인물이다.

## 서버 설정

기존 글쓰기와 같은 서버 환경변수를 사용한다. 이미지와 영상 연결은 별개이다.

```dotenv
LLM_ENABLED=true
OPENAI_API_KEY=
LLM_IMAGE_MODEL=gpt-image-2.6-flare
FAL_KEY=
```

- OpenAI 키: 이미지 편집. `POST https://api.openai.com/v1/images/edits`, 실제 사진을 `images[].image_url`에 전달, JPEG 1024×1536 한 장 생성.
- fal 키: `fal-ai/kling-video/v3/pro/image-to-video` 모델로 6초 생성. `start_image_url`에 확인한 AI 사진을 전달한다. 모델 자체 음성·음악은 끄고 앱의 기존 배경음악을 합성한다.
- 로컬은 `.env_dev`, EC2는 운영 `/etc/majungmul/.env` 또는 개발 `/etc/majungmul/.env_dev`에 설정하고 서버를 재시작한다. 키는 서버에서만 읽고 `VITE_` 접두사를 붙이지 않는다. UI의 연결 표시는 설정 유무이며 실제 사용 권한·잔액 검증은 생성 요청으로 확인한다.
- 영상 키가 없으면 영상 생성 버튼을 비활성화한다. 사진 확대 효과를 실제 생성 영상으로 표시하지 않는다.
- Sora/Videos API는 2026-09-24 종료되어 사용하지 않는다.

## 작업·비용·저장

생성 버튼을 눌렀을 때만 유료 요청한다. 이미지 요청은 최대 180초, 영상 접수·상태 조회는 30초. 자동 유료 재시도는 없다. 접수 응답을 못 받은 경우 중복 과금을 피하려면 공급자 이용 내역을 먼저 확인한다. 기존 앱은 로그인 없이 동작하므로 외부 공개 시 인증된 접근 경로와 사용자별 예산이 필요하다. 서버 프로세스당 생성 12회/시간·동시 2회로 제한한다(멀티 서버 간 공유되지 않음).

영상은 비동기 큐를 사용하며 10초마다 최대 약 15분간 조회한다. 통신 실패나 대기 시간 초과 후에는 **영상 상태 다시 확인**으로 기존 작업을 조회한다. 작업 번호와 24시간 만료 시각을 서버에서 HMAC 서명하여 클라이언트에 반환한다. 조회 주소는 고정된 공급자 경로에서만 구성한다. 결과 URL은 HTTPS fal.media 도메인만 허용한다.

이미지·서명된 작업 정보·완성 URL은 현재 브라우저 localStorage에 최근 6개까지 저장한다. 서버 DB나 다른 기기에 동기화하지 않는다. 같은 가게·사진 선택으로 돌아오면 이어서 확인할 수 있다. 공간이 부족하면 저장 실패를 표시한다. 페이지를 새로고침하는 동안 진행 중이던 이미지 요청 또는 아직 접수 응답을 받지 못한 영상은 복구되지 않을 수 있다. 완료 영상 파일은 브라우저에서 재생·합성하므로 제공자 CDN의 CORS와 유효한 다운로드 URL이 필요하다. 서비스 URL이 만료되기 전에 최종 파일을 저장한다.

## 검증

`npm test`, `npx tsc --noEmit`, `npm run build:ec2`.

자동 테스트는 메뉴 제약, 프롬프트, 실제 이미지 편집 요청 구조, 비동기 영상 접수/조회, 서명 위변조·만료, 중복 접수 방지, 오류 후 재조회, 다른 글로 이동한 후 결과 보존 및 30초 장면 배치를 검증한다. 영상 서비스의 실제 생성 품질은 `FAL_KEY`가 연결된 환경에서 별도 확인해야 한다.
